## v5.30：精算待ちへの状態変化を通知条件に統一（2026-11-01）

- ユーザー方針：JRA結果が確定したことだけを知らせるのではなく、**購入済み馬券の状態が「結果待ち → 精算待ち」に変わること**を通知・音声の条件とする。
- 公開PWA `monitor-target-export.js` の監視対象から `officialReady===true` または `specialManualResult===true` の馬券を除外。従来 `status==='pending'` のみでは、精算待ちの馬券もまだ `pending` なので外せなかった。
- `registerVerifiedResults` は新しい検証済み結果を馬券に登録したとき、既存 `save()` から `baken:wagers-updated` を発火。これにより `monitor-auto-sync.js` がすぐに監視対象を再同期し、精算待ちになったレースをサーバー側の対象から外す。新規結果を1枚以上受け取った場合だけ `result-auto-sync.js` が `baken:new-settlement-ready` を発火し、音声ONなら前面アプリでMP3を再生。
- アプリ終了中、iOSはブラウザ内部の馬券タブを監視できない。サーバーは**事前同期されている結果待ちレース**と、独立検証済み `final` 結果が一致した場合だけプッシュ通知し、受信後アプリ起動時にデータを取得して精算待ちへ進む。1端末・1レース1回の通知履歴を維持。
- **注意**：iPhoneが結果待ちから精算待ちへ変わる瞬間とサーバー通知時刻は厳密には一致しない。前面MP3とプッシュ通知は異なる仕組み。購入・精算の履歴、残高、手動精算は変更しない。
- Public `index.html` をv5.30、`monitor-target-export.js?v=3` に更新。Vercelの追加デプロイは不要（今回の変更は公開PWAの監視対象抽出のみ）。**iPhone実機での再同期・実通知の最終確認は次の開催待ち**。
- **動作確認ポイント**：①結果待ち購入中は監視対象として登録、②実際に精算待ちになった瞬間にアプリから対象が解除される、③アプリが閉じていた場合にはその前に検証済み結果に対する通知を受け取る、④精算済み・古い結果への重複通知がない。

## 将来の完成像

### 1. 実レース連動（最優先の技術課題）

- JRAの実際の開催日・競馬場・レース番号・出馬表・馬名・馬番を表示。
- 実際のオッズに基づく**仮想馬券の購入**、購入時点の条件記録。
- レース確定後、実際の着順・払戻金で仮想馬券を判定・精算。
- 購入締切・取消・返還・同着などの例外処理を検討。
- **合法・利用規約に適合し、安定して利用できるデータ取得方法が未確立。** JRA公式の自由利用可能な無料APIは確認できていない。JRA-VAN等は費用・ライセンス・再配信条件を要確認。無断スクレイピングや権利上不明なデータの公開を前提にしない。
- 無料で安定した自動取得ができない場合は、手動入力・ユーザー提供データなどの段階的な代替案を検討する。**架空デモと実レースを混同させない。**

### 2. マークカード式の購入体験

- 券種・レース・馬番・購入額を、**紙のマークカードを鉛筆で塗るような操作**で選択。
- 複数買い目や金額入力を直感的に扱えるようにする。
- **「演出は本格的に、操作は簡単に」**を原則とし、毎回の購入が面倒にならない設計。
- 将来の発券・払戻演出にはスキップ設定を用意。

### 3. 自動発売機での仮想馬券購入

- マークカード投入 → 内容・金額確認 → 購入確定 → 馬券発券、という演出。
- 発券されたBaken-KING独自デザインの仮想馬券にレース名・券種・買い目・購入額等を印字。
- **馬券ホルダー**で購入した仮想馬券を券面として保管・閲覧できるようにする。

### 4. 払戻機での精算体験

- 馬券を払戻機へスワイプ投入 → 読み取り → 的中・不的中判定 → 払戻金表示、という演出。
- **実際の残高・精算データは確定結果に基づいて処理し、機械操作は演出**にする。払戻演出を見忘れても資金が失われない仕組み。
- 効果音・アニメーションは最後に磨き込み、スキップ可能にする。

### 5. フレンド機能＋ランキング（将来機能）

**リアルタイム対戦ルームを主目的にしない。** 基本は各自が自由に1人で遊び、競馬好きの友達と成績を見比べられる仕組み。

- ニックネーム・フレンドコードなどで少人数の友達を登録。
- **フレンドランキング**：生涯回収率、月間収支などを中心に比較。将来は週次・年間・的中率・レース別も検討。
- フレンドのプロフィールから仮想残高、回収率、累計収支、購入レース数、得意券種などを閲覧。
- 友達の買い目公開は**発走後**を基本に、プライバシー設定も検討。
- 回収率ランキングには最低購入額・最低購入レース数などの参加条件を検討（少額1回の大穴的中だけで上位固定になるのを防ぐ）。
- 将来のフレンド機能には認証・クラウドDB・改ざん防止策が必要。無料枠の範囲で開始できるか検証。**現状は全データが端末ローカルであり、他ユーザーとの共有はできない。**
- 既存の5タブを維持し、「データ」にランキング、「設定」にフレンド管理を設ける案。
- 対戦ルーム・同期レース勝負は**必須機能ではない**。ユーザーが重視しているのは気軽な成績比較。

### 6. 継続して楽しめる成績管理

- 初期仮想資金10万円からの資金推移、生涯回収率・累計収支・的中率。
- 期間別・券種別・競馬場別等の分析を将来的に拡張。

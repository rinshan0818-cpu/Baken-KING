## 友達登録・成績比較・自動同期

- ログインはNeon Authを使うメール・パスワード方式。メール確認が必要な場合は6桁コードを使用。設定の友達管理でプロフィール登録、申請、承認を行う。
- **同意画面は初回からなし**。本番モードで認証済みなら、ログイン後に成績アップロードを試みる。口頭で了承した少人数運用を前提にする。
- 同期は**15分間隔**。表示中に60秒ごとのタイマーで最終アップロード時刻をチェックし、必要な場合に同期する。アプリ復帰（visibility/focus）ではログインと友達の情報を再確認する。
- アプリを閉じた間やiOSがPWAを停止している間、15分ごとに自動実行される保証はない。これはサーバー側のJRA結果監視5分間隔と異なる処理。
- 「データ→友達比較→成績を同期→自分の9項目を今すぐ同期」は手動同期として利用可能。「設定→アカウント・友達→友達の成績を更新」で相手を再取得。
- 比較表示は9項目：収支、回収率、購入金額、払戻金額、精算済み馬券数、購入レース数、的中レース数、レース的中率、最高払戻金。
- クラウド送信は7つの集計元フィールド：`stakeYen`, `returnedYen`, `settledTicketCount`, `purchasedRaceCount`, `hitRaceCount`, `settledRaceCount`, `maxPayoutYen`。**馬券の買い目、馬券履歴全文、残高、精算履歴全文を友達向けに送信しない**。
- 友達承認と成績の送信・相手端末での取得は別々。購入0件なら有効な0値を共有。テストモードでは共有しない。共有データとログイン状態がない場合に「未登録」を誤用しない。

## v1.01：長期間未起動時の表示と保存

| 状況 | 最新の動作 |
|---|---|
| 成績取得成功 | 比較値と**最終取得日時**をローカルに保存・表示。 |
| 通信・APIエラー | 有効な前回の友達成績は消さず、旧データ表示と「通信エラー」「前回取得した成績を表示中（最終同期日時）」を案内。 |
| HTTP 401／認証期限切れ | 「再ログインが必要です」と案内し、前回の友達集計キャッシュは残す。 |
| 認証済みで友達一覧が空 | 「友達登録はありません」。古い友達比較キャッシュは消去。 |
| 認証済みで相手の集計が本当に存在しない | 「未登録／未共有」。通信不能とは別扱い。 |
| 別アカウントにログイン | キャッシュ所有者IDを照合し、異なるアカウントの友達成績は削除・非表示。 |
| 明示ログアウト | 友達比較キャッシュを消去。本人の馬券・残高・精算履歴は消さない。 |

- 友達の表示値の保存キー：`baken-king-friend-score-v1`、所有者`baken-king-friend-score-owner-v1`、友達`baken-king-friend-score-friend-id-v1`。
- 最終**受信**日時：`baken-next-friend-fetched:<userId>`。最終**送信**日時：`baken-next-score-last:<userId>`。この2つは異なる。
- 主要実装：`app-next-cloud.js`、比較表を含む`index.html`。通信切断による旧表示の維持は、端末に有効なキャッシュが存在するときだけ。
- **保証範囲**：数日間開かないだけでサーバーの成績を削除する設計ではない。ただしSafariのサイトデータ削除、PWAの削除、端末変更、Cookie期限切れ、Neon・Vercel側の障害、OSの保存制限まで保証はできない。

## データ構成と安全方針

- 馬券購入・残高・精算履歴は原則端末内`localStorage`（既存`keiba-demo-v1`）。ログインだけで別端末へ自動コピーされない。バックアップ保存／復元は別の機能。
- アカウント認証、プロフィール、友達関係、友達向け集計はNeon Auth、認証付きVercel APIとNeon DBで管理。
- アプリは本番・テストモードを分離。テスト馬券を本番精算や友達成績・JRA監視に混ぜない。
- 原則5人程度の小規模利用。URL変更なし。既存の馬券・残高・精算履歴・アカウント・本番DBを試験目的で初期化しない。任意のシーズンリセット／全件削除を一般画面に戻さない。

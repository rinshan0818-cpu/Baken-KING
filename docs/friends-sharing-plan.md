# Baken-KING｜友達との共有機能 設計 v0.1

作成日：2026-11-02／対象：v5.63（UI凍結、実レーステスト継続）

## 目的と初期スコープ

友達と**仮想馬券ゲームの成績**を安全に共有する。まず2人で試し、その後少人数へ拡張する。初期版は**閲覧専用**であり、友達の馬券を買う・精算する・残高を操作する機能は持たない。実際の賭博・決済・金銭送金は扱わない。

公開するもの（初期版）：
- 表示名、公開用の累計購入額・払戻額・収支・回収率・精算済み馬券件数
- 必要な場合のみ「精算済みの馬券」の一覧（デフォルト非公開）
- 公開範囲：承認した友達だけ。本人にはプレビューを用意

公開しないもの：
- 未精算の馬券（予想内容の先出しやネタバレ防止）
- 通知購読情報、JRAアクセスURLや監視用キー、端末識別情報
- 診断ログ、予想メモ、タグ、バックアップJSON全体
- プライベートなテストモードの馬券・残高

## 技術的な前提

- 現行PWA本体：GitHub Pages。保存キー：本番 `keiba-demo-v1`、テスト `baken-king-test-state-v1`。
- 結果監視・通知は別系統で運用。共有の公開APIを既存の監視・通知APIへ混ぜない。
- 共有機能の作業は**別ブランチ／独立モジュール**から始め、v5.63の5タブを維持する。
- クラウドで扱うのは明示的に公開対象とした**最小限のスナップショット**。旧localStorageデータを無条件・自動でアップロードしない。
- サーバーには認証と権限検査を必須とする。GitHub Pages公開HTMLに秘密鍵を埋め込まない。

## リリース段階

### P0：共有用データの生成とテスト（本番画面には追加しない）

- 端末内の馬券データから、公開可能な数値だけを取り出す**純粋関数**を作る。
- `visibility='summary'` を初期値とし、決済済みの詳細は別途 opt-in にする。
- 異常値・未知の馬券状態・破損した入力は公開しない（fail closed）。
- 自動テスト：未精算馬券除外、テストモード除外、本人以外のデータ混入防止、元データ非変更。

### P1：アカウント・友達承認（新しい認証バックエンド）

- 招待リンク／招待コードから相手が登録。メール認証などで本人確認。
- `users`、`friend_requests`、`friendships`、`public_snapshots` をサーバー側で管理。
- 友達が承認するまでは公開データを取得できない。退会・友達解除で閲覧権限を直ちに失う。
- **ユーザーIDはサーバーが認証から確定**。リクエストの `userId` を信頼しない。
- 各読み取り・書き込みで必ずアクセス制御。DBのRLS等で二重に保護する。
- レート制限、招待コードの期限・失効、プロフィールの最小公開、認証情報の安全保管を実施。

### P2：明示的な公開同期

- 初回同期前に、公開する項目・範囲・保存先を示し利用者が同意する。
- **本番の既存馬券は端末が正本のまま**。サーバーへ送るのは集計スナップショットであり、移行・同期しても端末の残高と購入処理には介入しない。
- 同期失敗は端末側に記録し、購入・精算を妨げない。
- 公開情報の更新はオンデマンドから開始。自動同期は権限・復旧手順を検証してから追加。
- 解約・同期停止・閲覧権限撤回の動作を設ける。

### P3：相互閲覧・ランキング・履歴（追加機能）

- 友達一覧、承認済み相手の公開成績、期間別比較。
- 追加同意がある場合だけ精算済み馬券の個別閲覧。
- WIN5の個人成績は将来追加し、まだ公開スキーマを拡張しない。

## 公開スナップショット例（案）

```json
{
  "schemaVersion": 1,
  "profileId": "server-issued-id",
  "updatedAt": "server-time",
  "visibility": "friends",
  "summary": {
    "stakeYen": 12000,
    "returnedYen": 10500,
    "profitYen": -1500,
    "roiPercent": 87.5,
    "settledTicketCount": 17
  }
}
```

`profileId`、`updatedAt`、`visibility` はサーバーが確定する。クライアントには集計可能な数値だけを提出させ、サーバー側でスキーマと整数上限を検証する。数値の正当性を実際の購入と証明する仕組みではないため、ランキングは原則自己申告の仮想成績として扱う。

## 移行・安全性

1. 既存v2バックアップをiPhoneで保管し、テストモード・本番モードの保存キーを維持。
2. ブラウザで現行動作を回帰テスト。旧データの自動変換・上書きはしない。
3. 認証と公開のプレビューをテストユーザー2名で確認する。
4. 友達の未承認状態／友達解除後／ログアウト後は閲覧不可をサーバー側で検証する。
5. 既存の監視・通知を壊さないことを11月7日・8日の実レースで検証した後、P1/P2の本体統合を判断。

## 未確定の仕様

- 招待方法：招待コードを基本候補。メールリンク・Appleログイン等は利用サービスの制約を調べて決定。
- 成績の公開範囲：初期値は友達に対するサマリーのみ。詳細馬券は公開しない。
- 認証・DBサービス：既存Vercelとの連携、費用、無料枠、RLS/認証仕様を比較して決める。
- アカウントを複数端末で共有する場合の本番データ移行は**別フェーズ**。今回の友達向け閲覧機能に混ぜない。
